# F12.7 Inboxul social

- **Pasul:** F12.7, faza 12. Depinde de F9 (canalele sociale), F12.1 (CRM). Context: `docs/17` §17.8.
  Construit de sesiunea A (D-007, D-024). Migrarea `0100`.
- **Gata când:** mesajele de test sunt clasificate corect.
- **Hotărâri de proiectare.**
  - **Canalele agenției** (Instagram, Facebook), citite doar după aprobarea proprietarului din `/crm/inbox`
    (`crm_inbox_canale`, cu cine a aprobat). Oprirea unui canal oprește citirea.
  - **Citirea trece prin ușa executorului** (`app.operare.efecte.inbox` → `app.connectors.inbox`), ca orice
    atingere a unei platforme (garda `check_efecte`). Conectorul e `InboxSimulat`; cel real e Graph API (ADR-07).
  - **O singură dată pe mesaj** (unic pe canal și id extern); cursorul `citit_pana_la` pe canal.
  - **Clasificare pe reguli** (D), fără diacritice, în ordinea prudenței: spam/abuz → sensibil (sănătate,
    juridic, bani) → critică → cerere de preț → întrebare → laudă → neclar. Clasa și motivul se păstrează pe
    mesaj; fiecare clasificare lasă urmă (`inbox / clasificare`).
  - Jobul `crm.inbox` citește la 5 minute. Ecranul `/crm/inbox` (proprietar): canale, mesaje filtrate pe clasă.
- **Teste de acceptare.** `tests/unit/test_crm_inbox.py` (17 mesaje de test, toate cele 7 clase din 17.8),
  `tests/integration/test_crm_inbox.py` (aprobarea canalului din panou, citirea, recitirea fără dubluri, canalul
  neaprobat și cel oprit nu se citesc, filtrul, urmele; operatorul primește 403).
- **NEVERIFICAT / SIMULAT.** Conectorul real (aprobarea aplicației la Meta, permisiunile de mesagerie), regulile
  pe mesaje reale (precizie și rapel necalibrate), TikTok și LinkedIn (fără API de mesaje potrivit în v1).
