# F15.3 Exercițiul de restaurare completă

- **Pasul:** F15.3 (`docs/23` §23.18). *Gata când:* platforma e refăcută din backup pe un mediu curat, în ținta de
  timp. Ținta: 4 h (`docs/runbooks/restaurare.md`, docs/22 §22.6).
- **Hotărâri (D-007, D-022).** `scripts/exercitiu_restaurare.py`, cap-coadă și cronometrat pe etape:
  1. **backup** real, cu uneltele de producție (`infra/backup/ama_backup.py`: pg_dump, media, configurare, age,
     rclone), cu o cheie de proprietar nouă, generată pentru exercițiu;
  2. **mediu curat:** o bază NOUĂ și un director media NOU; între sursă și destinație trece doar copia (manifest
     verificat, decriptare, `pg_restore` cu proprietarii și drepturile, dezarhivarea media);
  3. **verificare:** aceeași versiune de migrări, același număr de rânduri pe FIECARE tabel (inclusiv cozile
     motorului), aceleași tabele cu RLS activ și forțat, fișiere media identice (sha256), aplicația pornită pe baza
     restaurată ca rolul aplicației răspunde `/readyz` = 200;
  4. **durata** față de țintă; peste țintă = picat. Nimic necriptat nu rămâne (directorul de lucru se șterge).
- **Teste.** `tests/avarie/test_restaurare.py` (în catalogul avariei, A14): exercițiul pe Postgres-ul local de test
  trece; cu ținta 0 h aceleași verificări trec, dar exercițiul pică.
- **Rezultat local:** trece în câteva secunde (bază de test mică).
- **De verificat la migrare.** Exercițiul pe staging, cu copia reală de la destinația externă și cu volumul real de
  date și media; un server nou (instalare-vps.md) ca „mediu curat” complet; durata reală notată față de 4 h.
