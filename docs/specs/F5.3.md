# F5.3 G2 Verificatorul de fapte

- **Pasul:** F5.3, faza 5.
- **Context:** `docs/09` §9.3 (registrul de fapte: mecanismul anti-halucinații) și §9.4 (G2 la V1 și V3); `docs/13` §13.1 (lume închisă: autorul nu adaugă cifre, prețuri sau
  promisiuni) și §13.5 (după editare, G2 rulează din nou); F4.6 (registrul de fapte: `fapte.pentru_context`, verificatorul de citate și normalizarea cifrelor din `creier.citat`), F4.7
  (`oferte.pentru_context`: ofertele cu fapte legate aprobate și valabile). Există cadrul (F5.1) și infrastructura judecătorului (F5.2).
- **Hotărâri de proiectare.**
  1. *Extragerea afirmațiilor este întâi deterministă* (`afirmatii.extrage`, nucleu pur): `pret` (număr + monedă, lei ≡ RON), `procent`, `termen` („în 2-3 zile”), `data`
     (și „din 2019”), `ora`, `cifra` (orice alt număr despre client), `superlativ`, `comparatie`, `promisiune` (liste de expresii în `date/afirmatii.toml`, scrise fără diacritice,
     deci prind și textul fără ele). Fragmentul este EXACT din text; linkurile, hashtag-urile și adresele de email nu sunt afirmații; „3 pași simpli”, numerotarea listelor și anii singuri
     nu sunt afirmații despre client. Numerele se normalizează cu `creier.citat.numere_din` (1.200,50 = 1200,5), nu cu un model.
  2. *Potrivirea este exactă* (`acoperire`): prețul și moneda trebuie să existe în registru; dacă lângă preț apare numele unei oferte / al unui fapt, prețul trebuie să fie al LUI
     („Abonamentul Lunar costă 49 lei”, unde 49 e prețul altui produs, este `pret_diferit`); prețul de referință se acceptă doar prezentat ca preț anterior („în loc de 59 lei”);
     reducerea % se acoperă din registru sau CALCULATĂ din preț și preț de referință (toleranță de rotunjire 0,5 puncte); termen, dată, oră, cifră: aceeași valoare (și unitate de timp) într-o
     intrare; superlativ / comparație / promisiune: cuvintele ei semnificative (rădăcini de 6 litere) trebuie să apară în ACEEAȘI intrare. Registrul gol nu acoperă nimic.
  3. *Registrul* = faptele aprobate de un om și valabile la data publicării (`termen_la` al livrabilului, altfel data validării) + ofertele (cu `pret` / `pret_referinta`, fapte legate
     aprobate) + citate din surse de cercetare (`campuri["surse_citate"]`: un citat verificat LITERAL într-un pasaj al clientului acoperă; un citat care nu apare în pasaj, sau un pasaj
     al altui client, este o sursă inventată și blochează). Un fapt propus, expirat, viitor sau retras nu acoperă nimic.
  4. *O afirmație neacoperită sau diferită blochează* (`esec`, `majora`, deci reparație cu instrucțiunea: valoarea din registru sau scoate afirmația).
  5. *Fapt lipsă → întrebare, nu presupunere.* Livrabilul poate declara ce îi trebuie (`campuri["fapte_necesare"]`: `[{tip, subiect}]`) sau autorul poate cere explicit un fapt
     (`campuri["intrebari_autor"]`). Dacă registrul nu îl are, rezultă un verdict cu `detalii.intrebare` → decizia `INTREBARE` (peste reparație, sub carantină): se deschide o
     ÎNTREBARE (`validari_intrebari`, migrarea `0029`: vizibilă pe livrabil și în `validare.intrebari.deschise`), iar livrabilul trece în `coadă de erori`. Răspunsul NU devine fapt:
     faptul îl propune și îl aprobă un om în Creier, apoi un om reia livrabilul (`productie.reia_de_om`).
  6. *V3 opțional pentru afirmațiile nestructurate (fără cifre)*: judecător mic, prompt `validare.g2_afirmatii@1`, schemă strictă; primește registrul ca date (identificator + conținut) și
     textul ca DATE externe, propune fragmentul și faptul acoperitor. Verificarea e deterministă: fragmentul trebuie să apară literal în text, fără cifre (cifrele sunt ale extractorului),
     neacoperit deja de V1, iar `fapt_id` trebuie să fie un identificator din registrul trimis. Altfel blochează. Rulează doar după ce V1 a trecut (nu consumă cotă după un blocaj).
- **Ce se construiește.** `app/validare/{afirmatii,acoperire,verifica_fapte,intrebari}.py`, `date/afirmatii.toml`, promptul `validare.g2_afirmatii.v1`, migrarea `0029`, ramura `INTREBARE` din
  `ciclu.py`, secțiunea „Întrebări către client” din urma livrabilului, testele.
- **Ce nu se construiește.** Ecranul de răspuns la întrebări și biroul de aprobări (F5.9); verificarea cifrelor din imagini (F8); „sursele de cercetare citate” în afara pasajelor clientului (F6/F12);
  verificarea afirmațiilor despre concurență (alt registru).
- **Contracte.** `G2@1` (V1, ordine 30) → 1–2 verdicte; `G2@1` (V3). `validare.intrebari.{deschide, ale_livrabilului, deschise, raspunde, inchide}`. Intrarea livrabilului:
  `campuri["fapte_necesare"]`, `campuri["intrebari_autor"]`, `campuri["surse_citate"]`.
- **Teste de acceptare.** `tests/unit/test_validare_afirmatii.py` (extragere și acoperire, exhaustiv); `tests/integration/test_validare_g2.py`: **un text cu un preț greșit și unul cu o afirmație
  neacoperită sunt blocate, un text corect trece**; faptele expirate / viitoare / neaprobate nu acoperă; citatele din surse (literale, nu ale altui client); fapt lipsă → întrebare vizibilă →
  răspuns → fapt adăugat → reluare → validat; V3 cu verificare deterministă și fără apel după un blocaj.
- **NEVERIFICAT / SIMULAT.** Acoperirea listelor de superlative / promisiuni (parțială, în română); rata de fals-pozitive pe texte reale (ținta 9.9: cel mult 10% materiale bune blocate) se măsoară la F5.7;
  potrivirea după nume (rădăcini de 5 litere) poate confunda produse cu nume asemănătoare; modelul V3 este FALS.
- **Riscuri.** RT1 (halucinații: acesta este mecanismul), fals-pozitive care blochează texte bune (de aici instrucțiunea clară și alternativa: întrebarea către client).
- **Module atinse.** `app/validare`, `app/panou/productie_web.py`, `livrabil.html`, `prompts/`, migrări, teste.
- **Depinde de** F5.1, F5.2, F4.6, F4.7. **Deblochează** F5.4 (pachetele de reguli refolosesc `Problema`), F6 (autorii primesc instrucțiunile G2), F5.7 (setul de aur).
- **Revizuire obligatorie:** nu.
- **Întrebări deschise.** Cine decide dacă un „cel mai bun” fără premiu poate sta într-un text (acum: nu); dacă livrabilul care așteaptă un răspuns expiră (acum: rămâne în coadă de erori până îl reia un om).
