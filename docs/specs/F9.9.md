# F9.9 Site și blog (H6)

- **Pasul:** F9.9, faza 9. Depinde de F7.1 (blogul), F7.10 (articolele), F9.1, F9.7. Context: `docs/15` §15.1.
- **Hotărâri de proiectare (D-007).**
  - Articolul F7.10 nu mai trebuie publicat direct: `seo.articole.scrie(..., publica=False)` îl întoarce, iar
    `publicare.blog.pregateste` îl face livrabil `articol` pe canalul `blog` (conținutul: titlu, descriere, adresă,
    corp, surse citate, brieful) trece cascada de validare pe livrabil (F5, fără trimiterile [n]) și cere aprobarea. Comportamentul implicit din F7.10 rămâne neschimbat.
  - Canalul `blog` nu cere aprobare de platformă: cu contul configurat, e automat; după aprobare se programează
    (F9.7) și pleacă prin executorul de efecte. Lista on-page se verifică din nou pe versiunea aprobată chiar
    înainte de plecare; dacă nu trece, nu pleacă.
  - `ConectorBlog`: **găzduit** (blogul platformei, al agenției: `site.blog.publica`, idempotent pe adresă) sau
    **WordPress** (CMS-ul clientului: REST API v2, parolă de aplicație Basic, ținută criptat; `verifica` după
    adresă). WordPress nu are OAuth (parola se dă din panou) și nu declară limite.
- **Contracte.** `publicare.blog.{configureaza_gazduit, pregateste, pachet}`,
  `connectors.publicare.blog.{ConectorBlog, html_articol}`, `seo.articole.scrie(publica=)`.
- **Teste de acceptare.** `tests/integration/test_publicare_blog.py`: **un articol aprobat din F7.10 apare pe blogul
  agenției, cu verificările on-page trecute** (nimic pe blog înainte de aprobare); `tests/contract/test_conector_blog.py`
  (WordPress simulat; HTML-ul articolului scăpat).
- **NEVERIFICAT / SIMULAT.** Modelul FALS (ca în F7.10); WordPress simulat. Un WordPress real al unui client
  (versiune, module de securitate, parola de aplicație), alte CMS-uri: la migrare.
