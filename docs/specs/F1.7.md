# F1.7 Coaja panoului (aplicație instalabilă)

- **Pasul:** F1.7, Coaja panoului, faza 1.
- **Context:** există conturi, 2FA, sesiuni, CSRF, audit și antete CSP stricte (F1.4–F1.6). Lipsește interfața: doar paginile de autentificare. Secțiunile 18.1, 18.2, 18.6, 7.8, 22.4. „Gata când” din plan: instalezi aplicația pe telefon și primești o notificare de test. Fără telefon și fără staging (D-001), criteriul se adaptează: testele automate dovedesc manifestul, service worker-ul, paginile și conducta de notificări push; instalarea pe un telefon real rămâne în „De verificat la migrare”.
- **Ce se construiește.**
  1. Pachetul `app/panou/`: pagini randate pe server (Jinja2), HTMX 2.0.4 și Alpine.js 3.14.9 (varianta CSP), vendorizate în `app/web/static/vendor/` cu nume, versiune și SHA-256 în `VENDOR.md` (testul recalculează sumele). Fără CDN, fără lanț de build, fără JS sau CSS inline.
  2. Bara de jos cu cinci file: Acasă (`/`), Aprobări, Producție, Alerte, Meniu. Aprobări, Producție și Alerte sunt stări goale oneste („încă nimic aici — apare în faza F2”). Meniu trimite la Operare (F1.8/F1.9), cont și 2FA, setările de notificări și ieșire. Toate cer utilizator de agenție cu 2FA încheiat; rolurile de client primesc 403 (portalul este faza F7).
  3. Acasă: starea sistemului (versiune, mediu, bază, backup, livrare) și butoanele de oprire din 7.8 (vezi F1.10). Oprirea este imediată (direcția sigură, auditată); repornirea trece printr-o pagină de confirmare. Actualizare periodică a stării cu HTMX.
  4. Temă: variabile CSS, mod luminos și întunecat după `prefers-color-scheme`, ținte de atingere ≥ 44 px, focus vizibil, `safe-area-inset`, text în română cu diacritice.
  5. PWA: `/manifest.webmanifest`, pictogramele 192/512/maskable (PNG generate cu biblioteca standard de `scripts/genereaza_icoane.py`), `/sw.js` din rădăcină (`Service-Worker-Allowed: /`, `Cache-Control: no-cache`). Service worker-ul ține în cache doar fișiere din `/static/`, niciodată HTML sau API; afișează notificarea la `push` și deschide/focalizează aplicația la `notificationclick` (doar adrese din aceeași origine). Meta iOS (`apple-mobile-web-app-*`, `apple-touch-icon`). CSP primește doar `worker-src 'self'` și `manifest-src 'self'`.
  6. Web Push: dependența `pywebpush==2.3.0` (semnare VAPID + criptare RFC 8291; scrisă de la zero ar fi cod criptografic propriu). Tabelul `abonamente_push` (pe utilizator, `endpoint` unic; fiecare utilizator își atinge doar rândurile, agenția citește și poate șterge abonamente moarte). Rute: `POST /notificari/aboneaza`, `/dezaboneaza`, `/test` (CSRF prin `X-CSRF-Token`). Cheile VAPID vin din mediu; fără ele push este dezactivat curat și pagina o spune. Trimiterea trece prin `app/operare/notificari.py`, cu trimițător injectabil; 404/410 șterg abonamentul.
  7. Niveluri din 18.6 (`Nivel`: critic, important, informativ) și regula de rutare ca funcție pură: critic → push + Telegram; important → push; informativ → rezumat zilnic (substituent: nu se trimite nimic acum).
- **Ce nu se construiește.** Ecranele reale (Aprobări F2.9, Producție, Alerte, Clienți etc.); portalul de client (F7); preferințe pe tip de notificare și ora rezumatului (pas ulterior: acum nivelul decide canalul); rezumatul zilnic; chei VAPID rotite din interfață; reasocierea unui dispozitiv între conturi (un endpoint ținut de alt cont dă 409).
- **Contracte de date.** `abonamente_push(id, utilizator_id, endpoint UNIQUE, p256dh, auth, user_agent, creat_la, ultima_trimitere)`, RLS pe `utilizator_id`. Sarcina utilă a notificării: JSON `{titlu, text, url, nivel}`; fără secrete și fără date personale. Variabile: `AMA_VAPID_PUBLIC_KEY`, `AMA_VAPID_PRIVATE_KEY` (secret, niciodată în jurnale), `AMA_VAPID_SUBJECT`. Cheile se generează cu `python scripts/genereaza_vapid.py`.
- **Teste de acceptare.**
  1. Manifestul este JSON valid cu câmpurile cerute; pictogramele există, sunt PNG reale de mărimea declarată.
  2. `/sw.js` are tip JavaScript, vine din rădăcină, cu `Service-Worker-Allowed: /`; nu ține în cache HTML.
  3. Cele cinci pagini se afișează pentru un proprietar cu 2FA, anonimul este trimis la login, clientul primește 403.
  4. Niciun șablon nu are `<script>` inline, `style=` sau atribute `on*=`; sumele fișierelor vendorizate corespund.
  5. Abonare → „trimite notificare de test” apelează trimițătorul fals cu sarcina corectă; 410 șterge abonamentul; fără chei VAPID, push este dezactivat și UI-ul spune asta.
  6. Izolare: utilizatorul B nu vede și nu șterge abonamentul lui A; rutarea pe niveluri este testată pe toate cele trei niveluri.
- **Riscuri.** RT1 (26) nu se schimbă. Notificarea nu are garanții de livrare (furnizorul push); de aceea cele critice merg și pe Telegram. Cheia VAPID privată compromisă permite trimitere către abonații existenți: rotație prin regenerare și reabonare.
- **Module atinse.** `app/panou`, `app/operare/notificari.py`, `app/operare/antete.py`, `app/web`, `app/config.py`, `app/main.py`, migrarea `0005`, `scripts/`.
- **Depinde de:** F1.4–F1.6. **Deblochează:** F2.9, F1.10.
- **Revizuire obligatorie:** da (securitate: CSP, service worker, RLS).
- **Întrebări deschise.** Culoarea și numele definitiv al agenției (provizoriu „AMA”, DECIZII.md). Ora rezumatului zilnic.
