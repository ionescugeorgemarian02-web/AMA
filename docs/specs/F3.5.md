# F3.5 Modelul local și modelul de embeddings

- **Pasul:** F3.5, Modelul local și modelul de embeddings, faza 3.
- **Context:** `docs/06` §6.3–6.4 (llama.cpp cu model cuantizat de 7–9 mld, ținut încărcat; „ocupă un culoar greu cât generează”;
  embeddings „în afara culoarelor grele”; viteza se măsoară în F3.5), `docs/08` §8.1/§8.2/§8.6 (decodare constrânsă de gramatică),
  `docs/10` §10.5, ADR-04. Există rutarea (lanțuri de degradare cu `nivel:local`, F3.4), cozile cu culoare grele (F2.2).
- **Ce se construiește.**
  1. *Adaptorul `local`* (`adaptoare/local.py`, tip de API nou): server compatibil OpenAI separat (llama.cpp `llama-server` sau
     Ollama), în rețeaua internă, FĂRĂ biblioteci grele în imaginea aplicației. Fără cheie; `cache_prompt`; ieșire structurată prin
     schema JSON în `response_format` (serverul generează doar text conform schemei); viteza raportată de server (`timings`);
     timp maxim din parametrii furnizorului (`timeout_sec`, 600 s pentru generare pe procesor).
  2. *Registru* (migrarea `0018`): `http://` acceptat doar spre nume de serviciu intern / localhost; capabilitate `embeddings`;
     `tokeni_pe_secunda`, `viteza_masurata_la`, `dimensiune_vector` pe model. Sămânța (`inventar_local`, totul `[I]`, inactiv):
     furnizorul `local` cu trei mărimi (3B, 7B, 9B cuantizate) și furnizorul `vectori` cu `multilingual-e5-small` (384).
  3. *Culoarul greu* (decizie): modelul local se apelează DOAR din joburi de pe coada `greu`. Jobul ocupă un culoar cât generează
     (limita de culoare a cozii este exact semaforul din 6.4, fără un mecanism în plus) și serverul are un singur slot
     (`--parallel 1`). Gateway-ul află coada jobului (`motor.coada_curenta()`, din starea fluxului); în afara coadei `greu` (job `io`,
     script, proces web) modelul local este exclus din rutare (`Motiv.LOCAL_COADA`). Când el e singura cale (degradare) →
     `ApelRefuzat("local_doar_pe_coada_greu")`, NU `Amanat`: o reîncercare pe aceeași coadă dă același rezultat; fluxul prinde codul și
     își mută pasul pe `greu` (`motor.trimite(…, coada=Coada.GREU)`). Motiv pentru refuz în loc de „amână”: o amânare ar bucla la
     nesfârșit pe `io`; un cod clar face greșeala de proiectare vizibilă.
  4. *Vectori:* `gateway.vectorizeaza(texte, *, tenant_id, componenta, prioritate) -> list[list[float]]` (cel mult 64 de texte de
     cel mult 20 000 de caractere) și `gateway.dimensiune_vectori(tenant_id)`. Model separat, pe propriul server, apelat din
     worker-light / `io` / web, fără coada `greu`. Dimensiunea din registru se verifică la fiecare răspuns (altfel
     `FurnizoriIndisponibili`); server căzut → reîncercări, întrerupător, `Amanat`. Jurnal doar cu metadate (fără textele
     clientului). Modelul se alege doar dintre cele cu `antrenare_pe_date` fals. Modelele de vectori nu intră în lanțurile de text.
  5. *Măsurarea:* `python -m app.gateway.masurare [--model COD …] [--cereri 3] [--tokeni 96]`: prompt fix în română, mediana vitezei
     (a serverului sau tokeni/durată), scrisă în registru și în audit; un model neservit rămâne nemăsurat.
  6. *Compose* (`infra/compose/base.yml`): serviciile `local-llm` (6,5 GB, `--mlock`, `--parallel 1`, volum de modele) și `embeddings`
     (0,7 GB), profil `local-llm`, imagine din `AMA_IMAGE_LOCAL_LLM` (NEVERIFICAT: fără digest, de aflat la migrare; până atunci nu
     pornesc, ca să nu strice livrarea).
  7. *Pregătire pentru F3.6:* `gateway.apeleaza(…, model="furnizor/identificator")` (un singur model, fără lanț), `Rezultat`/jurnal
     neschimbate.
- **Ce nu se construiește.** Descărcarea sau rularea unui model real; alegerea modelului local final (după măsurătoare și F3.6);
  coloana pgvector și căutarea hibridă (F4.3); „P3 pe local oricând există un culoar liber” ca programare (F11); mascarea textelor
  trimise la vectori (merg doar la serverul propriu).
- **Contracte de date.** `gateway.vectorizeaza`, `gateway.dimensiune_vectori`, `gateway.apeleaza(…, model=…)`;
  `motor.coada_curenta()`; coduri: `local_doar_pe_coada_greu`; coloane noi pe `gateway_modele`.
- **Teste de acceptare.** `tests/integration/test_gateway_local.py`: `test_o_clasificare_de_proba_ruleaza_prin_adaptorul_local_pe_coada_greu`,
  `…_modelul_local_nu_se_apeleaza_din_afara_culoarului_greu`, `…_un_vector_se_calculeaza_cat_timp_toate_culoarele_grele_sunt_ocupate`
  (motor real, două culoare ocupate), `…_comanda_de_masurare_noteaza_viteza_…` (server fals pe socket real, trei mărimi),
  `…_adaptorul_local_vorbeste_cu_serverul_pe_http_real`, `…_samanta_locala_…`; `tests/unit/test_gateway_masurare.py`.
- **NEVERIFICAT / SIMULAT.** Niciun model local nu a rulat: serverul este un HTTP fals în forma API-ului llama.cpp. Steagurile
  llama.cpp din compose, healthcheck-ul și digestul imaginii sunt neverificate; „în limitele de memorie” (6,5 GB) nu s-a putut
  măsura; viteza reală pe procesorul VPS-ului este necunoscută; modelele din sămânță sunt exemple `[I]`, licențele neconfirmate;
  forma exactă a `response_format` la llama.cpp/Ollama și `timings` sunt după documentație, din memorie.
- **Riscuri.** Memoria (modelul + 2 culoare de randare pe 24 GB); un job greu blocat de generare lungă (timeout 600 s).
- **Module atinse.** `app/gateway` (adaptor, vectori, măsurare, rutare, apel, client, registru, candidat, modele), `app/operare/motor`
  (`coada_curenta`), migrarea `0018`, `infra/compose/base.yml`, teste (`furnizor_fals`, `server_local_fals`, `gateway_utile` — corectat:
  curățarea furnizorilor cu cod ales).
- **Depinde de** F3.1–F3.4, F2.2. **Deblochează** F3.6 (rulare pe modelul local), F4.3 (vectori), F11.
- **Revizuire obligatorie:** da (infrastructură, memorie).

  imaginea aplicației nu poartă biblioteci de inferență)? Cine confirmă licența modelului local?
