# F13.1 Citirea rezultatelor Meta

- **Pasul:** F13.1, faza 13 (sesiunea A). Context: `docs/16` §16.1, §16.7, §16.10; `docs/20` „Reclame”. Migrarea `0070`.
- **Gata când:** cifrele contului agenției apar în panou și coincid cu managerul de reclame.
- **Hotărâri (D-007, D-008).**
  - Contul de reclame (`reclame_conturi`) ține plafoanele din contract (zilnic, lunar, pe campanie) și regulile
    gardianului (16.4) încă de acum: sunt ale contului, nu ale unei campanii.
  - Citirea trece prin ușa executorului (`app/operare/efecte/reclame.py`), spre conectorul din
    `app/connectors/reclame/meta.py` (`/act_<id>/insights`, pe campanie și pe reclamă, pe zile, cu paginare).
  - Banii se țin în subunități (bani), întregi; cheltuiala-text a platformei se convertește exact (`Decimal`).
  - Ultimele 3 zile se recitesc la fiecare oră (atribuirea le corectează); prima citire aduce 30 de zile. Rândul
    se rescrie (cheie: cont, nivel, obiect, zi), deci nu se dublează. Totalul contului = suma campaniilor.
  - Eroare de autentificare → `autentificare` + motivul pe cont (F13.5 o tratează ca anomalie); eroare temporară →
    `amanat`, fără nimic scris.
- **Ecran:** `/reclame` (cheltuiala zilei și a lunii față de plafon, 30 de zile), `/reclame/cont/<id>` (total, pe
  campanii, pe zile). Cere `rapoarte.citeste` și scop de agenție.
- **Teste:** `tests/integration/test_reclame_meta.py`, `tests/unit/test_reclame_meta.py`; Marketing API SIMULAT
  (`tests/platforme/meta_ads.py`, cu evidența proprie a „managerului”).
- **NEVERIFICAT:** forma reală a răspunsurilor (versiunea Graph, numele acțiunii de conversie `lead`, fusul orar
  al contului), accesul `ads_read` (App Review), tokenul din `publicare_conturi` pe canalul `meta_ads`. La migrare.
